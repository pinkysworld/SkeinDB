R13 · Consistency & Distribution

Causal Consistency via ETag Chains

SkeinDB's query validators now pair ordinary ETags with `vector_clock_v2` causality tokens so clients can demand reads that are at least as fresh as earlier observations. The runtime combines `if_none_match` with `min_causality`, emits dependency-backed response tokens, preserves backward compatibility for older `etag_chain_v1` request payloads, and now propagates the same watermark across replicated writes.

Hardened Runtime — `vector_clock_v2` causal validators, replication-causality fanout, and cache interaction tests are live.

🔬 What's Novel

  • `vector_clock_v2` causal token format encoding dependency versions that travel alongside ordinary query ETags
  • `query.select`, `query.execute_prepared`, `merge.apply`, and `vector.search` all accept `min_causality` and emit response `causality` tokens
  • Replicated writes carry `x-skeindb-replication-causality`, and replicas expose the merged watermark through `cluster.status` and `stats.snapshot.cluster.replication`
  • Prepared-query cache validation combines `if_none_match` and `min_causality`, returning `not_modified` only when both the ETag and dependency floor are satisfied
  • Legacy `etag_chain_v1` request tokens remain accepted while clients migrate to the current runtime format

🔧 Technical Approach

Phase 1 — Causal ETag Design

The current runtime uses a hybrid dependency clock: {"format":"vector_clock_v2","deps":[...]}. Responses emit the v2 format, while request parsing still accepts legacy etag_chain_v1 tokens for compatibility.

Phase 2 — Consistency Protocol

query.select and query.execute_prepared accept min_causality and emit response causality tokens. Matching if_none_match validators return not_modified only when the requested dependency floor is also satisfied.

Phase 3 — Cluster Integration

Cluster replication now forwards `x-skeindb-replication-causality` alongside replicated writes, and replicas merge the applied watermark into `cluster.status.replication.causality` plus `stats.snapshot.cluster.replication.causality` without imposing a global total order.

Phase 4 — Caching Interaction

Cache interaction coverage is live: focused tests verify satisfied and rejected combinations of if_none_match and min_causality for prepared queries, alongside the existing query-select validator coverage.

🧪 Hypotheses

H1

Causal ETags encoding vector clocks or similar structures propagate correctly through standard HTTP caching infrastructure.

H2

Causal consistency provides meaningfully lower latency than serializability for geo-distributed deployments.

H3

Incremental causal ETag updates based on query dependencies are more efficient than full vector clocks per response.

Frequently asked questions

Is any feature locked behind a paid plan?

No. Every capability — MVCC storage, MySQL + PostgreSQL wire, SkeinAdmin, all 20 research tracks, clustering, audit WAL — ships in the open-source binary under Apache-2.0. Paid plans only change our response time and channels.

Can I use SkeinDB in a commercial product without a support plan?

Yes. Apache-2.0 grants you commercial use, modification, redistribution, and an explicit patent grant. See the Licensing page for details. A support plan is only useful if you want a defined SLA and a direct contact.

Can support start with a short pilot or migration sprint?

Yes. Short, scoped engagements are possible when that is the best way to de-risk adoption. The pricing page lists example add-ons such as a migration sprint or workshop, but the exact scope is agreed through the commercial inquiry.

Who is behind SkeinDB?

SkeinDB is built by Michél Nguyen (ORCID) with contributions from community members. Commercial engagements are currently operated as an independent practice; invoicing details are provided on signature.

How do commercial engagements work in practice?

Start with the contact page or the public commercial inquiry issue. Once the workload is understood, the engagement is scoped and quoted directly. GitHub Sponsors and PayPal remain the easiest options for public support.

What about compliance or regulated workloads?

SkeinDB is currently a self-hosted open-source database, so compliance is primarily a property of the environment you run it in. Enterprise and Custom engagements can include architecture review, security hardening guidance, and audit-WAL setup, but there is no separate managed-service compliance program today.

Do you offer hosted / managed SkeinDB?

Not generally available yet. A private hosted pilot is offered as an add-on for Enterprise and Custom customers. General availability is on the roadmap after the 1.0 on-disk format freeze.

Can paid engagements influence the roadmap?

Yes, commercial work can prioritize items that fit the project direction. What it cannot do is fragment the open-source core, hide correctness fixes, or turn shared infrastructure into a private fork by default.

How can I support the project if I’m not ready for a paid plan?

Anything helps: GitHub Sponsors, PayPal, starring the repo, filing high-quality issues, or sponsoring a single research track. See the Licensing & sponsorship page for the full list.
